RulesForge 0.9.3-rc.1 qualifies the current architecture and SDK integration against the Salts 2.3 and SaltsUtils 4.3 release candidates.

- Includes native Release SDKs for Linux x64, Linux ARM64, Windows x64, and macOS ARM64 in `RulesForge.Native.0.9.3-rc.1.nupkg`.
- Uses Salts 2.3.0-rc.5 and SaltsUtils 4.3.0-rc.2 during qualification; DataBind remains owned by SaltsUtils and requires ABI 10. Each SDK manifest records the exact resolved versions and source SHA.
- Preserves the 0.9.2 C API surface, session execution admission, and exact RHS WHILE iteration-limit behavior. The same session must still be caller-serialized.
- Synchronizes architecture, dependency ownership, execution lifecycle, and integration documentation. Planned bounded-execution features remain design work unless explicitly identified as implemented.
- Runs the existing 38 CTest entries on all four native platforms, with full configured builds and installation. Compiler, vcpkg binary, and SDK payload caches are separate.

This is a prerelease. CMake reports numeric version `0.9.3`; the C API version string and NuGet version are `0.9.3-rc.1`. Consumers must restore Salts.Native and SaltsUtils.Native explicitly with prerelease-aware resolution (`Version="*-*"`) and provide matching `SALTS_ROOT` and `SALTS_UTILS_ROOT`. The package does not embed transitive GitHub package version constraints or producer SDK payloads. The newer producer SDK requirements mean this RC is not qualified with the older stable dependency pair.

Debug/ASan, benchmarks, mobile platforms, and the separate installed-package consumer project are outside this release qualification. The package contains the installed public C ABI SDK surface, not the internal C++ engine API. Roll back by selecting the previous RulesForge package together with its matching producer SDKs; published packages and tags are not overwritten.
