RulesForge 0.9.3-rc.2 removes the unused direct BoringSSL build dependency from RC.1.

- Removes `boringssl` from the RulesForge vcpkg manifest and removes the root `find_package(OpenSSL REQUIRED)` call.
- Removes the NASM installation steps that were needed only for the direct BoringSSL source build, and updates the build requirements.
- Preserves the C API, rule execution behavior, and DataBind ABI 10 boundary. Producer SDK dependencies remain owned by Salts and SaltsUtils.
- Includes native Release SDKs for Linux x64, Linux ARM64, Windows x64, and macOS ARM64 in `RulesForge.Native.0.9.3-rc.2.nupkg`.

The release preparation runs the existing 38 CTest entries on each of the four native platforms, with complete configured builds and installation. The published package is the artifact from that successful preparation, with a SHA-256 checksum and per-platform manifests recording the exact source commit and producer SDK versions.

Consumers must restore Salts.Native and SaltsUtils.Native explicitly with prerelease-aware resolution (`Version="*-*"`) and set matching `SALTS_ROOT` and `SALTS_UTILS_ROOT`. This RC targets Salts 2.3 and SaltsUtils 4.3; DataBind requires version 3.0 or newer with ABI 10. CMake reports numeric version `0.9.3`; the C API and NuGet package report `0.9.3-rc.2`.

This is a prerelease. Debug/ASan, benchmarks, mobile platforms, and the separate installed-package consumer project are outside this release qualification. Existing published tags and packages remain unchanged.
